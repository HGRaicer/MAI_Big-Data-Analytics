# Отчёт по лабораторной работе №2

## Тема
ETL-пайплайн на Apache Spark с построением аналитической модели «звезда» в PostgreSQL и витрин в ClickHouse.

## Цель работы
Цель лабораторной работы — обработать исходные CSV-данные с помощью Apache Spark, построить модель данных типа «звезда» и сформировать аналитические отчёты в ClickHouse.

## Ход выполнения

Для выполнения работы использовались Docker Compose, PostgreSQL, Apache Spark и ClickHouse. Исходные данные состоят из 10 CSV-файлов по 1000 строк. При запуске PostgreSQL данные загружаются в сырую таблицу `mock_data`; после загрузки в ней находится 10000 строк.

Далее был реализован Spark-скрипт `01_build_star.py`. Он читает таблицу `mock_data` из PostgreSQL через JDBC, очищает значения, приводит числовые и датовые поля к нужным типам и строит аналитическую модель «звезда». В центре схемы находится таблица фактов `fact_sales`, где каждая строка соответствует одной продаже. Вокруг неё расположены измерения: `dim_customer`, `dim_seller`, `dim_product`, `dim_store`, `dim_supplier` и `dim_pet`.

 Справочные признаки, такие как категория товара, бренд, страна магазина или страна поставщика, хранятся внутри соответствующих измерений как обычные атрибуты.

После построения модели был реализован второй Spark-скрипт `02_create_clickhouse_reports.py`. Он читает таблицы звезды из PostgreSQL, рассчитывает агрегаты и записывает 6 витрин в ClickHouse: продажи по продуктам, продажи по клиентам, продажи по времени, продажи по магазинам, продажи по поставщикам и качество продукции.

## Проверка результата

Проверка показала, что в `mock_data` находится 10000 строк и в `fact_sales` также находится 10000 строк. Потерянных строк нет. Также проверено, что все факты имеют связи с покупателями, продавцами, товарами, магазинами, поставщиками и питомцами.

## Вывод

В ходе лабораторной работы был реализован полный ETL-пайплайн: исходные CSV-данные загружаются в PostgreSQL, затем Spark преобразует их в модель «звезда», после чего Spark формирует аналитические витрины и сохраняет их в ClickHouse. Данные были перенесены без потерь, связи между таблицей фактов и измерениями построены корректно, а итоговые витрины готовы для аналитических запросов.
