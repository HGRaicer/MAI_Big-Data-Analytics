# Отчёт по лабораторной работе №1

## Тема
Построение аналитической схемы типа «снежинка» на основе CSV-файлов с данными о продажах.

## Цель работы
Цель лабораторной работы — загрузить исходные данные в PostgreSQL, проанализировать их структуру, выделить основные сущности и построить нормализованную схему хранилища данных с таблицей фактов и таблицами измерений.

## Ход выполнения

Для выполнения работы был поднят контейнер PostgreSQL через Docker Compose. Исходные данные состояли из 10 CSV-файлов, каждый из которых содержал по 1000 строк. Был выбран автоматический вариант загрузки через SQL-скрипты.

Все CSV-файлы были помещены в папку `data` и загружены в сырую таблицу `mock_data`. В этой таблице получилось 10000 строк. На этапе загрузки также возникла проблема с тем, что вместо CSV могли скачиваться HTML-страницы GitHub, поэтому файлы были перекачаны через raw-ссылки и переименованы в нужный формат.

После импорта была изучена структура таблицы `mock_data`. В ней находилось 50 колонок, а каждая строка описывала одну продажу. При этом в одной строке были смешаны данные о покупателе, питомце, продавце, товаре, магазине, поставщике и самой сделке. Поэтому исходная таблица была денормализованной и содержала много повторяющейся информации.

На основе анализа была спроектирована схема типа «снежинка». В ней была создана одна таблица фактов `fact_sales` и набор таблиц измерений: страны, города, типы питомцев, категории товаров, категории питомцев, бренды, поставщики, магазины, покупатели, продавцы, товары и питомцы. Такая структура позволяет хранить справочные данные отдельно и не дублировать их в каждой продаже.

Для создания таблиц был написан DDL-скрипт. Сначала создавались независимые справочники, затем зависимые таблицы измерений, и в конце таблица фактов. Для заполнения таблиц был написан DML-скрипт. Данные брались из `mock_data`, очищались и распределялись по соответствующим измерениям. Для удаления дублей использовались `DISTINCT`, `DISTINCT ON` и уникальные ключи. Для сущностей, у которых не было готового уникального идентификатора, были сформированы natural key на основе значимых полей.

После заполнения измерений была создана таблица фактов `fact_sales`. В неё попала каждая продажа из исходной таблицы. Вместо текстовых данных в таблице фактов хранятся ссылки на измерения: покупателя, продавца, товар, магазин и питомца. Также в факте хранятся дата продажи, количество товара, общая сумма и рассчитанная цена за единицу.

## Проверка результата

После выполнения всех скриптов была выполнена проверка качества загрузки. В сырой таблице `mock_data` оказалось 10000 строк, и в таблице фактов `fact_sales` также оказалось 10000 строк. Количество потерянных строк равно 0. Также было проверено, что все записи в таблице фактов имеют связи с покупателями, продавцами, товарами, магазинами и питомцами.

Результат проверки:

| Показатель | Значение |
|---|---:|
| Строк в `mock_data` | 10000 |
| Строк в `fact_sales` | 10000 |
| Потерянных строк | 0 |
| Строк без связей с измерениями | 0 |

Дополнительно были созданы представления для проверки схемы и простого анализа данных: количество строк в таблицах, выручка по странам магазинов, выручка по брендам, выручка по категориям товаров, топ покупателей и выручка по типам питомцев.

## Вывод

В ходе лабораторной работы были успешно загружены 10 CSV-файлов, выполнен анализ исходных данных и построена нормализованная схема типа «снежинка». Данные были разделены на таблицу фактов и таблицы измерений, что позволило убрать дублирование и подготовить базу для аналитических запросов. Проверка показала, что все 10000 строк были перенесены корректно, без потерь и без нарушений связей между таблицами.
